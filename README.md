# VoxArbor Node

*Українською. English: [README.en.md](README.en.md).*

Робочий вузол [VoxArbor UA](https://github.com/voxarbor): голосові сервіси для української мови на власному
комп'ютері. Розпізнавання мовлення, озвучення, переклад українською, відновлення пунктуації та розпізнавання мовців.
Усе за одним портом і одним токеном. Вузол може обслуговувати один ПК або бути одним із багатьох вузлів
координатора. Без хмари і без чужих API-ключів.

**Що відкрите.** Вузол (усі сервіси, оновлювач) та інсталятор `install.sh` відкриті: це цей репозиторій. Координатор
VoxArbor (сайт і розподіл задач між вузлами) закритий. Вузол дає йому лише запити до голосових сервісів, без доступу
до вашого комп'ютера ([docs/security.md](docs/security.md)). Модель перекладу NLLB-200 (некомерційна ліцензія
CC-BY-NC) типово вимкнена.

Ідея VoxArbor: люди об'єднують свої комп'ютери в мережу, яка перекладає й озвучує відео українською. Більше на
[github.com/voxarbor](https://github.com/voxarbor).

Працює й на самому процесорі, але без відеокарти повільно. На старому ноутбуці (i7-4800MQ) розпізнавання мовлення
йде повільніше за реальний час, і перша озвучена фраза відео з'являється через ~42 с. З відеокартою NVIDIA (RTX 5070 Ti
Laptop) це ~2 с.

| шлях (шлюз) | що робить |
|---|---|
| `/tts/v1/audio/speech`, `/tts/v1/audio/speech/stream`, `/tts/v1/jobs` | озвучення українською (HolosTTS): цілі лекції, потокове відтворення (перший звук ~1,5 с), завдання з історією й субтитрами; чистить Markdown і посилання, читає англійські імена, числа, римські цифри, ініціали, дужки; словник наголосів |
| `/stt/v1/audio/transcriptions` | розпізнавання мовлення Whisper large-v3-turbo (сумісне з OpenAI) |
| `/translate/v1/translate`, `/translate/v1/punctuate` | переклад українською (Opus-MT), пунктуація, великі літери й речення для сирих субтитрів |
| `/diarize/v1/diarize` | хто й коли говорить, стать кожного мовця |
| `/fetch/v1/info`, `/fetch/v1/subs`, `/fetch/v1/audio` | за бажанням (`COMPOSE_PROFILES=fetch`): дані, субтитри й аудіо YouTube з IP цього вузла |
| `/capabilities` | що вміє цей вузол (схема 1) |

## Найпростіше: команда з сайту координатора

Якщо вузол буде частиною мережі VoxArbor, на сайті координатора в розділі «Мої вузли» є готова команда встановлення
для Linux і WSL. Скопіюйте її й виконайте в терміналі: вона сама поставить вузол і підключить його до вашого
облікового запису. Це той самий `install.sh` з цього репозиторію. Як звірити його контрольну суму перед запуском і що він
робить, крок за кроком: [docs/install.md](docs/install.md#встановлення-одним-скриптом-installsh).

## Запуск вручну

Потрібні Docker із compose v2, ~25 ГБ диска (з відеокартою ~35 ГБ), бажано 16 ГБ RAM і 4+ ядра.
```
cp .env.example .env
sed -i "s/^NODE_TOKEN=.*/NODE_TOKEN=$(openssl rand -hex 32)/" .env
docker compose --env-file .env pull
docker compose --env-file .env --profile init run --rm init-opus
docker compose --env-file .env up -d
```
Перший запуск завантажує образи (~11 ГБ без відеокарти, ~27 ГБ з нею), ~3,7 ГБ моделей перекладу і модель
розпізнавання мовлення. Далі кожен запит іде на `http://<хост>:8790` (`GATEWAY_PORT`) із заголовком
`Authorization: Bearer <NODE_TOKEN>`.

Вузол за NAT або для публічного координатора може сам підключатися назовні (`COORDINATOR_URL` і `NODE_JOIN_CODE`
у `.env`, див. docs/connect.md). Тоді відкривати `GATEWAY_PORT` не треба.

Відеокарта NVIDIA: додайте в `.env` рядок `COMPOSE_FILE=compose.yaml:compose.gpu.yaml`. Тоді розпізнавання мовлення,
озвучення й розпізнавання мовців працюють на відеокарті.

Щоб вузол не заважав власникові ПК, увімкніть економний режим `NODE_MODE=gentle`: одна задача одночасно й половина
потоків процесора.

З версії 0.13.0 вузол оновлюється сам (сервіс `updater`, лише з підписаних релізів, лише під час простою, з
відкотом у разі збою). Режим задає `UPDATER_MODE` у `.env`: `auto` (типово), `notify` або `off`.

Моделі завантажуються в пам'ять на вимогу й вивантажуються після 2 хвилин простою.

Оновлення, очищення старих образів, відеокарта, економний режим: **[docs/install.md](docs/install.md)**.

## Документація

- `docs/install.md`: встановлення (`install.sh` і всі його параметри), оновлення, відеокарта, економний режим, очищення.
- `docs/security.md`: що вузол робить на комп'ютері, права оновлювача, перевірка релізів.
- `docs/updater.md`: автоматичне оновлення: безпека, протокол, відкат (англійською).
- `docs/gateway.md`: шляхи шлюзу, контракт `/capabilities` (схема 1), образи (технічний контракт, англійською).
- `docs/API.md`: API озвучення: параметри, завдання, SSE, словник (англійською).
- `docs/connect.md`: протокол підключення вузла до координатора (англійською).
- `NOTICE`: ліцензії моделей. NLLB-200 лише для некомерційного використання, а голоси StyleTTS2 названо на честь
  справжніх дикторів, тож обидва типово вимкнені.

## Розробка

Образи збирає GitHub Actions (`.github/workflows/images.yml`) у `ghcr.io/voxarbor/node-<сервіс>`. Вони публічні,
вхід не потрібен. Теги: `v<реліз>` (з кореневого `VERSION`), власна версія сервісу, `sha-<12>`, `latest`. На вузлах
закріплюйте `VOICE_CORE_TAG=v<реліз>`. До кожного релізу `.github/workflows/release.yml` додає файли вузла і
підписаний `manifest.json`. Тести `tests/test_speech.py` (обробка тексту, без моделей), `tests/test_pool.py` (черга)
і `tests/test_connect.py` (конектор) запускаються всередині образів.
